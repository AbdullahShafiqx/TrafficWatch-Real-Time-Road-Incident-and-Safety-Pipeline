About TrafficWatch Platform

PLATFORM CORE CONCEPT

TrafficWatch is an enterprise-grade distributed Big Data analytics pipeline designed for real-time vehicular incident classification, safety-threshold tracking, and regional risk assessment.

By combining automated live feeds with distributed computation and parallel scaling metrics, TrafficWatch equips transit authorities with the indicators needed to identify dangerous corridors and optimize traffic response networks.

Core Pipeline Architecture:
Hadoop HDFS PySpark SQL Structured Streaming TomTom API
PIPELINE OPERATIONS
1. Data Ingestion

Queries TomTom API for incidents along global transit zones and the Pakistan Transit Belt. Programmatically balances feed limits using local geographic projecting fallbacks.

2. Storage & Batch

Saves raw records in Hadoop HDFS. Executes Spark SQL batch routines to compute traffic classes, extract top dangerous corridors, and compile coordinates.

3. Real-Time Alerts

PySpark Structured Streaming connects to simulated TCP telemetry, flagging critical crashes (severity > 7.0) in real time and archiving warnings to HDFS.

4. Parallel Benchmarking

Validates cluster scaling capabilities across 1, 2, and 4 CPU cores, comparing empirical processing durations against Amdahl's Law limits.

Understanding Amdahl's Law

Amdahl's Law calculates the theoretical speedup limit of executing a program in parallel on $N$ cores: $$S(N) = \frac{1}{(1-P) + \frac{P}{N}}$$ where $P$ is the parallel fraction of the execution. In TrafficWatch, we assume $P = 0.85$, meaning $85\%$ of the Spark pipeline (data transformations, groupings) is parallelizable, and $15\%$ (JVM startup, driver communications, HDFS disk I/O) is sequential overhead.
